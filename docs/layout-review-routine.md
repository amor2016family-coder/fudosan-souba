# レイアウトの月次点検（Claude Code クラウド定期実行用の指示）

毎月1回実行する。**サイトに直接反映してはいけない。** 必ずプルリクエスト（変更の提案）として出し、人の承認を待つ。

---

あなたはこのサイト（住まい相場 / https://sumaisouba.com ）の見やすさを点検し、改善案を提案する担当です。

## 手順

1. `npm ci` のあと `npm run build` が通ることを確認する（`data/site.json` はリポジトリに入っている）。
2. 現在の見た目と構造を点検する。対象は `src/layouts/Base.astro`、`src/components/*.astro`、`src/pages/**`。
   - **スマホ（幅375px）を最優先**に見る。訪問者の大半はスマホ。
   - 確認する観点：
     - 文字の大きさと行間（本文は16px以上、数字は読み取りやすいか）
     - 表が横にはみ出していないか、列が多すぎないか
     - 最も知りたい情報（価格・㎡単価・前年比）が最初の画面に入っているか
     - 一括査定への導線が自然な位置にあるか（押しつけがましくないか）
     - 余白・見出しの階層・色のコントラスト（薄い文字になっていないか）
     - ダークモードでも読めるか
     - 用語が実態と合っているか（価格は中央値、データは取引価格情報であって成約価格ではない）
     - 画像や外部の読み込みを増やして表示が遅くなっていないか（外部フォントやJSの追加は避ける）
3. 改善点を**3つまで**選ぶ。効果が大きく、副作用が小さいものを優先する。一度に作り替えない。
4. 新しいブランチ（例 `layout/2026-10`）を作り、変更を実装する。
   - 必ず `npm run build` が通ることを確認する。
   - `data/`、`commentary/`、`scripts/`、`.github/` は変更しない。
   - 新しいライブラリを追加しない。JavaScriptに依存する表示にしない（静的なHTMLとCSSのまま保つ）。
   - 表示している数字の意味を変えない（中央値のままにする、計算方法を変えない）。
5. プルリクエストを作る（`gh pr create`）。本文には次を日本語で書く。
   - 変えた点（箇条書き3つまで）
   - なぜ良くなるのか（訪問者にとっての利点）
   - スマホ幅での確認結果
   - 迷った点や、やらなかったこと
6. **マージはしない。** 承認は人が行う。

## やってはいけないこと

- 本番への直接コミット（`main` への push）
- 履歴の書き換え（`git push --force`、`git rebase` して main を上書きすること）
- 見た目の全面的な作り替え、色使いの大幅な変更
- 広告や一括査定の導線を増やしすぎること（1ページに2か所までに保つ）
- 事実と異なる表示（「無料査定で高く売れる」など、根拠のない訴求）
